# StayEd — Session Summary (2026-08-05)

Summary of everything changed in this working session, grouped by feature. File paths are
relative to the repo root.

## 1. Teacher CLC Overview & Class Management

- CLC Overview now auto-scopes to the logged-in teacher's own municipality (read-only label)
  instead of a manual dropdown filter. Municipality filtering stays admin-only.
- Class Management is now scoped to one CLC at a time, shows Learning Level / CLC / School Year /
  Enrolled Learners per card (no modality tag), and adds a **Delete Class** action with a
  confirmation dialog and a real empty state.

**Files:** `StayEd_Frontend/pages/teacher/clc-overview.html`, `assets/js/teacher/clc-overview.js`,
`pages/teacher/class-management.html`, `assets/js/teacher/class-management.js`,
`assets/css/pages/teacher/clc.css`, `assets/js/core/api.js`, `assets/js/core/router.js`,
`assets/js/core/auth.js`, `assets/js/mock/mock-api.js` · `StayEd_Backend/app/routes/class_routes.py`
(new `DELETE /classes/<id>`, blocked with a 409 if learners are still enrolled).

## 2. Learner Records table consistency

Face-to-Face / Blended / Modular tables now share one layout (columns, widths, pagination,
typography); only modality-specific content differs. Fixed a row-action dropdown menu that was
clipped inside a scrolling table container (switched to `position:fixed` with computed
coordinates).

**Files:** `pages/teacher/learner-records.html`, `assets/js/teacher/learner-records-hub.js`,
`assets/css/pages/teacher/learner-records-hub.css`.

## 3. Module Release & Return Workflow (Module Release Logbook)

Modules are now released and returned as **batches** (multiple modules across multiple learning
strands in one transaction) instead of one at a time, shown as a chronological logbook with
per-batch status (Returned / Partially Returned / Active / Moderate Risk / High Risk based on
days since release) and partial-return support (per-module checkboxes + "Return All").

**New DB migration:** `StayEd_Backend/sql/06_module_release_batches.sql` — adds
`module_release_batch` table + `release_batch_id` FK on `module_record`, with a backfill so
pre-existing module records aren't lost.

**Backend:** `app/routes/learner_routes.py` (replaced the old one-module endpoints with
`GET /learners/<id>/modules`, `POST /learners/<id>/module-batches`,
`POST /learners/<id>/module-batches/<id>/return`).

**Frontend:** `assets/js/teacher/module-management-modal.js` (full rewrite — Logbook / Release
form / Return modal as one modal instance), `assets/css/pages/teacher/learner-records-hub.css`,
`assets/js/core/api.js`. Also fixed a latent bug in `assets/js/components/modal.js` where a
custom modal's CSS wrapper class never got cleared, silently leaking into unrelated modals opened
afterward (e.g. Delete Class) — every `Modal.show()`/`showCustom()` call now resets the modal card
class list first.

## 4. Learner Import CSV template

Added six optional columns (Re-enrollee, Employment Status, Distance from CLC, Civil Status,
Contact Number, Guardian Contact Number) to the downloadable template. These are never flagged by
validation. Also wired the bulk-import endpoint to actually **persist** these fields — previously
the importer silently discarded them even when a teacher filled them in.

**Files:** `assets/js/core/utils.js` (`downloadLearnerImportTemplate`) ·
`StayEd_Backend/app/routes/learner_routes.py` (`_canonical_rows` aliases, `_insert_import_rows`).

## 5. Learner Profile Revision

Removed the redundant/manual prediction UI; header now shows School Year, Date Enrolled, Assigned
Teacher, Current Class. Overview replaced Attendance-based metrics with Engagement Score, Modules
Released/Returned/Active, Last Activity, Days Since Last Return (attendance is no longer part of
this page). Risk Trend now plots real discrete risk-level history instead of a fabricated smooth
line. Risk Explanation rewritten around real contributing factors (module-return inactivity,
engagement score, re-enrollee, years enrolled — no more probability/confidence/model jargon).
Interventions tab is now fully functional: Assign / Update Status / Add Outcome all persist for
real (previously toast-only stubs), with proper empty states. Background Information fields moved
into a new, real **Edit Learner** modal.

**New DB migration:** `StayEd_Backend/sql/07_learner_4ps.sql` — adds `is_4ps_beneficiary` to
`learner`.

**Backend:** `app/routes/learner_routes.py` (rewritten `GET /learners/<id>/profile`, new
`_engagement_score`, new intervention endpoints `POST /learners/<id>/interventions`, fixed a
data-loss bug in `PUT /learners/<id>` where partial edits could silently reset `is_re_enrollee`),
`app/routes/intervention_routes.py` (new `PATCH /interventions/<id>`,
`POST /interventions/<id>/follow-up`), `app/services/prediction_service.py` +
`app/routes/prediction_routes.py` (extracted a reusable `trigger_prediction()` so module-return
and intervention actions can best-effort trigger a re-score in the background — see the
MODEL_COMMAND note below).

**Frontend:** `pages/teacher/learner-profile.html`, `assets/js/teacher/learner-profile.js` (full
rewrite), `assets/css/pages/teacher/learner-profile.css`, `assets/js/core/api.js`.

## 6. Teacher Dashboard filter bar

Fixed the "Learning Level" tab group overflowing its container ("Senior High" text clipped) —
it was sharing generic `flex:1` sizing with much narrower dropdown filters next to it.

**Files:** `components/dashboard/filter-bar.html`, `assets/css/pages/teacher/dashboard.css`.

## 7. Profile Settings page cleanup

Removed the Appearance, System Preferences, and Privacy sections (theme picker, font-scale
slider, compact mode, default landing page, language/timezone, active sessions/login history) —
none of it was backed by real functionality. Removed the now-dead JS/CSS that only existed to
support those sections.

**Files:** `pages/teacher/profile.html`, `assets/js/teacher/profile-settings.js`,
`assets/css/pages/teacher/profile-settings.css`.

## 8. Admin/Teacher UI unification + font-size increase

Audit found the admin section (Dashboard, CLC Management, Settings, User Management) was a fully
separate, hand-rolled design system — its own color variables, its own `.card`/`.btn` styling with
hardcoded radii/shadows, ~276 hardcoded hex colors, and no shared component classes at all,
despite loading after the shared `variables.css`/`components.css`. This pass re-points admin's
CSS **values** onto the same shared `--st-*` tokens teacher pages already use (colors, card
radius/shadow/padding, badge colors, button/table/heading sizes) without changing either side's
HTML structure or class names. Also bumped the shared type scale ~2px per step (body 16→18px,
small 14→16px, page titles 28→30px, table text, card titles, buttons, etc.) so both sides read as
one consistently-sized system. Removed two dead CSS rules found along the way (`.st-page-title` /
`.st-page-subtitle` in `layout.css`, superseded by `.st-page-header-title` and confirmed unused
anywhere).

**Files:** `assets/css/variables.css`, `assets/css/layout.css`, `assets/css/components.css`,
`assets/css/pages/admin/admin-dashboard.css`, `admin-clc-management.css`, `admin-settings.css`,
`admin-user-management.css`, `assets/css/pages/teacher/learner-records.css`.

## What needs to be set up again

### Database
Nothing manual. `StayEd_Backend/app/db_bootstrap.py` runs automatically every time the backend
starts and applies any `sql/*.sql` file that hasn't been applied yet (it's idempotent —
`IF NOT EXISTS` guards throughout). Just restart the backend as usual (`.\start.ps1`) and
migrations `06_module_release_batches.sql` and `07_learner_4ps.sql` will be applied automatically.
If you ever run migrations manually instead, make sure those two get applied.

### Backend config
No new required config. One pre-existing gap that's now more relevant: **`MODEL_COMMAND`** (in
`StayEd_Backend/.env`) is still unconfigured, so `/predictions/run` and the new best-effort
auto-triggers after module returns / intervention changes will keep failing silently (caught,
never shown to the teacher) until a real trained-model bridge is wired up there. Risk levels shown
in the app reflect whatever's already in the `risk_assessment` table (e.g. from `seed_demo.py`) —
nothing in this session builds a real scoring engine.

### Frontend
Nothing to install — static site, no build step. If you're testing locally through a "Live
Server"-type tool and pages look stale after a pull, do a hard refresh / clear the tab's service
worker cache (Chrome: DevTools → Application → Service Workers → Unregister, and Storage → Clear
site data) — a stuck service worker on `localhost` was the cause of a stale-JS issue earlier in
this session, unrelated to these code changes themselves.
