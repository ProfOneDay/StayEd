# StayEd Flask Backend

This backend connects the existing StayEd teacher frontend to the project's PostgreSQL database and preserves the frontend's existing API abstraction.

## Stack

- Flask REST API
- PostgreSQL (`stayed_db`)
- JWT authentication
- CSV/XLSX/XLS learner import
- Optional external Random Forest bridge through `Rscript`

## What is implemented

### Authentication and accounts
- `POST /api/auth/login`
- `POST /api/auth/logout`
- `GET /api/auth/me`
- `POST /api/auth/register`
- `POST /api/auth/change-password`
- `POST /api/auth/forgot-password`
- `POST /api/auth/reset-password`
- `PUT /api/users/profile`

New teacher registrations are intentionally created as `INACTIVE` so they can be reviewed before they receive access.

### Teacher setup
- `GET /api/clcs`
- `GET /api/clcs/current`
- `POST /api/clcs`
- `GET /api/teacher-classes` (updated Class Management cards)
- `GET /api/classes`
- `GET /api/classes/current`
- `POST /api/classes`

### Learners
- `GET /api/learners`
- `GET /api/learners/<id>`
- `POST /api/learners`
- `PUT /api/learners/<id>`
- `DELETE /api/learners/<id>`
- `GET /api/learners/<id>/profile`
- `GET /api/learners/<id>/records-detail`
- `POST /api/learners/import/preview`
- `POST /api/learners/import`
- `GET /api/learners/import/summary`

### Dashboard, early-warning support, and notifications
- `GET /api/teacher/dashboard`
- `GET /api/predictions/summary`
- `GET /api/predictions/risk-distribution`
- `POST /api/predictions/run`
- `GET /api/interventions`
- `GET /api/notifications`
- `POST /api/notifications/<id>/read`
- `POST /api/notifications/read-all`
- `DELETE /api/notifications/<id>`

### Minimal administrator API
- `GET /api/admin/users/pending`
- `POST /api/admin/users/<id>/approve`
- `POST /api/admin/users/<id>/suspend`
- `GET /api/admin/model`

The original ZIP does not contain the administrator dashboard HTML, so these endpoints are ready for a future admin UI but are not linked from an existing admin screen.

# 1. Prepare PostgreSQL

Use the StayEd database scripts you already created.

1. In pgAdmin, run `01_create_stayed_database.sql` while connected to the default `postgres` database.
2. Connect to `stayed_db`.
3. Run your existing `02_stayed_schema.sql`.
4. Run this backend's `sql/01_backend_extensions.sql` **after** the core schema.
5. Run `sql/02_reference_clcs.sql` to add the CLC choices used by the updated setup wizard.

The extension adds only backend support tables for password resets, notifications, and learner-import summaries. It does not replace the existing 24-table StayEd schema.

> Important: your existing `02_stayed_schema.sql` is a development reset script. Do not rerun it after entering real data unless you intend to recreate the StayEd tables.

---

# 2. Create the Python environment

From the `backend` directory on Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

On macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
```

Edit `.env` and set your real PostgreSQL connection string. Example when PostgreSQL has a password:

```env
DATABASE_URL=postgresql://postgres:StayEd2026DB@127.0.0.1:5433/stayed_db
```

For your Docker container named `stayed-postgres`, make sure it is running first:

```powershell
docker start stayed-postgres
```

The provided example uses computer port `5433`, which maps to PostgreSQL port `5432` inside Docker.

Change `SECRET_KEY` and `JWT_SECRET_KEY` before any real deployment.

# 5. Start the frontend

The included frontend is already switched from mock mode to the Flask API:

```javascript
API_URL: "http://127.0.0.1:5000/api"
USE_MOCK_API: false
DEMO_MODE: false
```

Serve the project over HTTP. From the project root (the directory containing `pages` and `assets`):

```powershell
python -m http.server 5500
```

Then open:

```text
http://127.0.0.1:5500/pages/auth/login.html
```

Do not open the HTML using only `file://...`; the configured CORS origins expect an HTTP development server.

# 6. Learner import format

CSV/Excel import recognizes these main columns:

```text
lrn
name
birthdate
sex
level
modality
```

Aliases such as `learner_reference_number`, `full_name`, `learner_name`, `date_of_birth`, `dob`, `learning_level`, and `learning_modality` are also recognized.

LRN must contain exactly 12 digits. `sex` must be `Male` or `Female`.

A sample file is included as `sample_learners.csv`.

# 7. Random Forest integration

StayEd's real prediction endpoint is:

```text
POST /api/predictions/run
```

The endpoint intentionally does **not** invent a probability when no trained model is connected. Without a configured model bridge it returns HTTP `503`.

Because the current StayEd model work is in R, the backend supports an external JSON bridge. A template is included as:

```text
model_bridge_example.R
```

Typical setup:

```r
saveRDS(final_rf_model, "models/stayed_random_forest.rds")
```

Install `jsonlite` in R, then configure `.env`:

```env
STAYED_R_MODEL=models/stayed_random_forest.rds
STAYED_RISK_CLASS=NotCompleted
MODEL_COMMAND=Rscript model_bridge_example.R
```

`STAYED_RISK_CLASS` must match the probability-column name representing dropout/non-completion in the final trained model. If the final model uses `Dropped` instead, set it to `Dropped`.

The request's `features` object must use the **exact predictor names and factor encodings expected by the saved model**. This is the one part that cannot be finalized correctly until the final trained Random Forest artifact and its predictor schema are fixed.

Risk-tier mapping in the PostgreSQL schema remains:

```text
< 0.40       Low
0.40–<0.70   Moderate
>= 0.70      High
```

# 8. Register → approve workflow

A teacher registration is created as pending/inactive.

An administrator can approve it with:

```text
POST /api/admin/users/<user_id>/approve
```

Optional JSON body:

```json
{
  "employee_id": "ALS-TEACHER-002"
}
```

After approval, the teacher can sign in using the email/password used during registration.

# Development notes

- JWT access tokens expire after 12 hours.
- Passwords use Werkzeug password hashing; plain-text passwords are never stored.
- `MAX_CONTENT_LENGTH` is 5 MB, matching the current learner-import UI.
- Teacher-scoped learner/class/prediction endpoints require a `TEACHER` JWT.
- The backend reuses the existing StayEd data model rather than creating a competing learner/risk schema.
- The frontend's mock data files remain in the project for reference, but `USE_MOCK_API` is disabled.
