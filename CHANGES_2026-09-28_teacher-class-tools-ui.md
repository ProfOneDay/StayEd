# Teacher class tools UI revision — 2026-09-28

Frontend-only UI revision of the four class-tool pages opened from a class's Learner Records page: **Manage Modules**, **Import Learners**, **Manual Enrollment**, and **Assessment Scores**. No API contracts, validation rules, formulas, or URL parameters were changed. Every `data-*`/`id` hook used by existing JS or tests was preserved. Two real display bugs were found and fixed along the way (see "Bug fixes" below).

## Manage Modules

- **`pages/teacher/module-management.html`** — sentence-cased "Add module" / "Switch class".
- **`assets/css/pages/teacher/module-management.css`** — full rewrite, scoped under `body[data-page="Manage Modules"]`:
  - Catalog: one summary card (total modules / release progress bar+legend / active / returned) replacing the old 5 stat boxes; module cell merges the number tile, title, strand chip and topic; "Learners released" shows a mini progress bar; hover chevron on each row.
  - Detail view: back-link above the panel; header with number tile + title + meta line (strand chip, topic, status badge); actions restyled (Edit module outline, Release(N) primary, Archive as a text-button that reddens on hover); new stage-summary bar (not released / released / returned counts); Dates column merges release + return date with a small icon-button to edit the release date; all inline styles removed.
  - Full custom mobile (`≤767px`) table→card conversion (this page's table isn't part of the other pages' shared mobile table styling).
- **`assets/js/teacher/module-management.js`** — presentational-only changes: rewrote `renderCatalogView`/`renderCatalogRow`/`renderDetailView`/`renderDetailRow` to match the new markup; added a `revealAnimated()` helper so first loads/view-transitions animate in but filter/search re-renders don't replay the animation; sentence-cased every modal title/button label. No behavioral/logic changes.

## Assessment Scores

This page had already been substantially built out in a prior pass (sticky learner panel, `table-layout:fixed` AF5 table, mobile breakpoints). Verification found it already matched most of the spec, so work here was two targeted, verified bug fixes plus one missing responsive behavior:

- **Bug fix — Likelihood/Readiness column cut off at laptop widths** (`assets/css/pages/teacher/assessment-scores.css`): the AF5 table's `<colgroup>` columns were percentage-widthed (60/10/10/20) with a `min-width:1080px` floor on the table, forcing an internal horizontal scroll inside its ~778px-wide container at typical laptop widths — the Readiness/Competency column was effectively always off-screen. Changed the column widths to literal pixels (Pre 104px, Post 104px, Readiness 200px, label auto) and lowered the table's `min-width` to 620px, so the table now fits its container exactly with no scrolling needed at 1440/1024px, while still falling back to `overflow-x:auto` on genuinely narrow containers.
- **Bug fix — unassessed learners showed a numeric "0%"/likely reading instead of "Waiting for post-test scores"** (`assets/js/teacher/assessment-scores.js`): the summed post-test total (`sumRowScores`/`overallScorePost`) defaults to `0` (not `null`) when no FLT post-test field has been filled in, so the existing `value == null` checks in the preview box, the overall-row table cell, and the live keystroke-driven update never actually matched an unassessed learner — they all rendered a real percentage computed from an empty total. Added `hasAnyPostScoreInData()`/`hasAnyPostScoreInDom()` helpers that check whether *any* FLT post field actually has a value (independent of what it sums to), and used them to gate all three render paths. Verified: a genuinely unassessed learner now shows "Waiting for post-test scores" in neutral gray in both locations; typing a post score live-updates to the correct colored percentage; clearing it reverts to "Waiting…". The saved value and percentage formula are unchanged — only the pre-any-post-score display was fixed.
- **Added — learner panel becomes a horizontal chip row under 1024px** (`assets/css/pages/teacher/assessment-scores.css`): the learner list was still a full vertical list with LRN subtitles below 1024px; added a `max-width:1023px` rule converting it to a horizontally-scrolling row of compact avatar+name-only chips, matching the spec. Also made the learner header `position:sticky` under the top bar so "Save scores" stays reachable while scrolling a long AF5 form.
